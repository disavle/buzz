# Buzz API

Базовый адрес локально: `http://localhost:8080`. Всё в JSON, даты в ISO 8601 (`2026-10-15T21:00:00Z`). Типы запросов и ответов лежат в пакете `Shared`, клиент использует их же.

Все роуты, кроме `/health` и `/auth/*`, требуют заголовок `Authorization: Bearer <token>`. Без него ответ `401`.

| Метод | Путь | Тело / параметры | Ответ |
|---|---|---|---|
| GET | `/health` | | `ok` |
| POST | `/auth/register` | `RegisterDTO` (email, пароль от 8 символов, `locale` ru/en необязательно) | `TokenDTO`; `email_taken`, если email занят |
| POST | `/auth/login` | `CredentialsDTO` | `TokenDTO`; `invalid_credentials` при неверном пароле |
| GET | `/me` | | `UserDTO` (с `locale`) |
| PATCH | `/me` | `UpdateMeDTO` (лимит 1...2000 мг, `locale`) | `UserDTO` |
| GET | `/drinks` | `?query=` поиск по бренду и названию | `[DrinkDTO]`: общий каталог + свои |
| POST | `/drinks` | `CreateDrinkDTO` | `DrinkDTO` с `isCustom = true` |
| GET | `/entries` | `?from=&to=` (from включительно, to нет) | `[EntryDTO]`, новые сверху, без удалённых |
| POST | `/entries` | `CreateEntryDTO` (id генерирует клиент) | `EntryDTO`; повтор с тем же id вернёт ту же запись |
| DELETE | `/entries/:id` | | `204`; мягкое удаление; чужая запись даёт `404` |
| GET | `/sync` | `?since=` | `SyncDTO`: напитки и записи, изменённые после since, включая удалённые |
| GET | `/stats` | `?period=week\|month&tz=Europe/Moscow` | `StatsDTO` для графиков |

## Ошибки и языки

Приложение на русском и английском, а сервер не присылает текстов для пользователя. Любая ошибка выглядит так:

```json
{"error": "limit_invalid", "reason": "dailyCaffeineLimitMg is not between 1 and 2000"}
```

`error` — машинный код из `APIErrorCode` (пакет `Shared`), клиент переводит его через String Catalog. `reason` на английском и нужен только для отладки, показывать его нельзя. Если сервер пришлёт код, которого клиент ещё не знает, он раскодируется как `.unknown`, и клиент покажет общее сообщение.

| Код | HTTP | Когда |
|---|---|---|
| `invalid_body` | 400 | JSON не разобрался |
| `validation_failed` | 400 | прочая ошибка валидации |
| `invalid_date` | 400 | дата в query не в ISO 8601 |
| `email_invalid` / `password_too_short` | 400 | регистрация |
| `email_taken` | 409 | email уже занят |
| `invalid_credentials` | 401 | неверный email или пароль |
| `unauthorized` | 401 | нет токена или он неверный |
| `limit_invalid` / `locale_invalid` | 400 | PATCH /me |
| `drink_invalid` / `volume_invalid` | 400 | поля напитка или записи |
| `unknown_drink` | 400 | запись на несуществующий или чужой напиток |
| `entry_conflict` | 409 | id записи уже занят другим пользователем |
| `not_found` | 404 | нет такой записи или роута |
| `internal` | 500 | ошибка сервера |

Язык пользователя (`locale`: `ru` или `en`) хранится в профиле на будущее, для пушей и писем. При регистрации его можно передать явно, иначе сервер возьмёт его из заголовка `Accept-Language`. Названия брендов и напитков не переводятся.

## Как считается

- **Кофеин и сахар записи** считаются один раз при создании: `caffeinePer100ml × volumeMl / 100`. Если объём не передан, берётся стандартный объём банки.
- **Цена** приходит как `Decimal`, в базе хранится целым числом в копейках (`price_minor`).
- **Статистика** строится в часовом поясе из `tz` (по умолчанию UTC). `byDay` содержит все дни периода, включая пустые, `byHour` всегда 24 элемента, неделя начинается с понедельника.

## Синхронизация

Зачем она: приложение работает офлайн, все записи сначала сохраняются в SwiftData на телефоне. Синхронизация доносит их до сервера и забирает изменения с сервера: так данные не теряются при переустановке и одинаковы на iPhone и iPad. Без сервера приложение тоже работает, просто данные живут только на одном устройстве.

1. Первый вызов `GET /sync` без `since` отдаёт всё.
2. Клиент сохраняет `serverTime` из ответа и в следующий раз шлёт его как `since`.
3. Запись с `deletedAt != nil` клиент удаляет у себя.
4. Офлайн-записи клиент отправляет через `POST /entries` со своими id; повторная отправка безопасна.

Граница `since` включительная, и даты без миллисекунд, так что одна запись может прийти дважды. Клиенту достаточно делать upsert по id.

## Начальный каталог

Миграция `SeedDrinks` добавляет 6 напитков: Red Bull (обычный и Sugarfree), Monster (Energy и Ultra White), Burn, Adrenaline Rush. Значения примерные, их стоит сверить с этикетками.
